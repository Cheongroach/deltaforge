# DeltaForge 训练框架与研究迭代路线

当前是经过双硬件算子验证的编译原型，加上可操作的观测实验台。它还不足以支持顶会论文：自实现 PyTorch 基线、三个 prefill 形状、未接入完整模型，不能证明相对成熟系统的优势。

用户要求先获得能玩的 profile 学习版，再推进后续迭代。本版完成真实 CPU／CUDA 采集、离线时间线、模拟与练习；以下内容是下一阶段的研究与执行标准，不是已经完成的训练结果。

## 用什么问题连接真实需求

面向采用 GDN 混合注意力模型的训练／部署开发者，核心问题是：**满足精确结构契约的编译与梯度改写，是否能在异构后端上减少训练图与激活保存成本，同时保持完整训练步的数值和质量等价？**

推理使用场景保留为次级验证：固定 shape 高频重复、小 batch 的发射开销、NPU 后端算子可编译性。是否比 vLLM 更有效，要在它的实际 kernel 与服务条件上验证，不把 Python recurrence 当作 vLLM。

## 候选比选与阶段顺序

| 候选 | 需要解决的问题 | 比选依据 | 下一阶段定位 |
|---|---|---|---|
| 直接复用 FLA / FlashQLA | 当前基线太弱 | 同 shape、dtype、state、前后向与 packed API；锁 commit | 第一优先级：建立竞争基线 |
| PyTorch 自动反向传播 | 快速建立数学与模型 oracle | 梯度、保存 tensor 字节、graph 节点与完整步耗时 | 保留作对照 |
| 结构化 solve 的解析 VJP | 幂零展开让 autograd 图保存较多中间量 | 梯度等价、保存激活、重算开销、编译覆盖 | 候选核心技术 |
| 分块 checkpoint／重算 | 长序列的激活与状态成本 | 峰值显存、step time、可训练 batch、梯度等价 | 与解析 VJP 组合做消融 |
| 原生 Triton / AscendC backward | 框架原语可能不能充分融合 | 资源压力、访存、kernel 时间、维护成本 | 先有证据再投入 |
| 通用 shape-aware cache／dispatch | 编译收益因 shape 变化而回归 | compile miss、回本、padding waste、负收益回避 | 完整系统的一部分 |
| 多卡 FSDP／Megatron 接入 | 单卡收益可能被通信吞掉 | 完整 step、通信 overlap、有效 tokens/s、恢复 | 单卡闭合之后 |

解析梯度候选：若 \(Y=(I+L)^{-1}R\)，给定 \(dY\)，则

\[
dR=(I+L)^{-T}dY,\quad dL=-\operatorname{StrictLower}(dR\,Y^T).
\]

这是已有矩阵微分关系，不宣称原创。必须分别检查保存逆矩阵、保存 L 后重算、普通 autograd 的成本。保存 L 与保存逆矩阵同形状，仅切换这两个张量不自动证明显存减少；真正减少的可能是展开图的中间量。以 `saved_tensors_hooks` 和峰值显存作证据，不能靠张量个数猜测。

## 研究问题与能否证伪

| RQ | 假设 | 否定条件 |
|---|---|---|
| RQ1：结构化编译 | 领域契约能改善后端覆盖，保持梯度等价 | 需要近似才能通过，或合法输入存在错误 |
| RQ2：训练成本 | 解析 VJP／重算能改善完整训练步的时间或显存 Pareto | 只改善 forward，backward／重算／编译抵消收益 |
| RQ3：异构可迁移性 | 同一语义 IR 可以生成不同后端的有效执行计划 | 仅一个后端／单个形状成立，或依赖大量不可复用特例 |
| RQ4：真实系统 | 收益在成熟基线、真实模型／数据和多卡中仍存在 | 只胜过 Python oracle，或最终质量／吞吐没有收益 |

当前 910B4 T=512 回归就是反例信号，应保留并解释。通用性不能建立在删除慢形状或只报告最快配置的基础上。

## 下一次实际迭代的验收

1. 锁定 FLA / FlashQLA、框架、模型、tokenizer、数据与硬件软件栈的版本。保存公开可复建环境定义，并区别实采镜像与参考 Dockerfile。
2. 在小维度上完成 solve 的 double gradcheck、六输入梯度、连续 state handoff、长序列与 mixed precision。单算子的梯度通过不代表模型训练正确。
3. 接入真正的模型训练步，包含参数、loss、optimizer 和 backward。优先单层 GDN 对照，再完整的小模型；随机初始化教学模型与预训练模型验证分别标记。
4. 使用公开文本训练数据，记录来源、许可、版本、划分和 tokenization。随机算子夹具只用于数学／性能检查，不充当任务准确率证据。
5. 做自动梯度／解析 VJP／重算／编译／原生 kernel 的消融。记录峰值显存、每步时间、有效 token、编译时间、梯度误差、loss 轨迹与自然生成质量。
6. 每个关键结论至少做多次独立运行，固定相同数据顺序与预算，先注册主指标与失败条件，再收集结果。硬件／进程内相关样本不能当作独立重复。
7. 单卡闭合后接入训练框架与多卡。明确 native all-reduce 与跨厂商低频／CPU 同步的差别，不把二者当同一个分布式基线。

## 以 MLSys／ASPLOS 等会议为目标时缺什么

目标会议代表的是系统研究质量要求，不是录用承诺。还需要：

- **可推广的新技术**：例如结构与误差契约驱动的训练 lowering、跨后端成本／保存激活规划；仅实现一个缺失 converter 不够。
- **强基线**：成熟 GDN kernel、编译训练路径、checkpoint 方案、真实框架；不能只对比慢 eager。
- **完整系统结果**：真实模型／数据、质量等价、完整训练步、显存与吞吐、编译摊销、多个后端和有代表性的形状。
- **机制证据**：nsys／ncu 或对应 NPU profiler、保存激活与 graph 分析、消融、失败形状和不适用范围。
- **可复现资产**：锁版本、来源与许可、数据协议、原始结果、独立重复、公开代码和实验入口。

本版的真正价值是建立可解释的起点，保留实际反例，并让使用者先学会独立采集和判断。后续以证据决定要不要投入更复杂的 kernel 或多卡训练。
